# 메타케어

환자와 보호자가 같은 앱을 설치하고 각자 첫 실행에서 역할을 고릅니다. 환자는 복약을 기록하고 진료 일정을 관리하며, 보호자는 환자가 동의해 공유한 기록을 확인합니다. Expo SDK 58, React Native, TypeScript, Expo Router를 사용합니다. 진입점은 이 폴더이며, `caregiver/`에는 보호자 화면과 기존 설치본의 호환 코드가 있습니다.

## 두 휴대폰 연결하기

1. 각 휴대폰에서 [메타케어](https://metacare-patient-test.vercel.app/)를 엽니다. 환자는 **환자예요**를 선택하고 **내 관리 → 보호자 연결**에서 기록 공유에 동의한 뒤 8자리 코드를 만듭니다.
2. 보호자는 **보호자예요**를 선택하고 코드를 입력합니다. 코드는 10분 동안 한 번 쓸 수 있습니다. 역할은 이 기기에 저장되며 관리 화면에서 변경할 수 있습니다. 연결 전에는 코드 입력 화면에서도 역할을 바꿀 수 있습니다.

기존 [보호자용 주소](https://metacare-caregiver-test.vercel.app/)에서도 동일한 통합 앱을 제공합니다. 이전에 연결한 주소와 브라우저에서 기존 역할을 선택하면 데이터를 그대로 사용합니다. 보호자는 **예시로 살펴보기**로 둘러보거나, 환자와 연결한 후 **관리 → 미기록 알림 받기**에서 웹 알림을 켤 수 있습니다(iPhone은 홈 화면에 추가한 후 실행). 새 약봉투 사진 인증은 네이티브 설치 앱에서 가능합니다.

보호자 앱은 **오늘 / 기록 / 관리** 3개 탭입니다. 오늘 확인이 필요한 미기록, 날짜별 기록·공유 사진, 별명·연락처·미기록 표시 기준을 제공합니다. 기기별 인증 토큰, 10분 유효한 일회용 코드, 한 환자와 한 보호자의 연결, 접근 권한 검사, 연결 해제, 로컬 서버 재시작 후 복원을 구현했습니다. 복약 상태와 사진은 환자가 공유에 동의한 뒤 전송합니다. 연결 후 ‘다음 진료 공유’를 켜면 가장 가까운 진료 한 건의 병원명·날짜·시간도 전달합니다. 등록한 병원의 전화번호는 보호자 공유 대상에서 제외합니다. 네이티브 토큰은 SecureStore, 브라우저 미리보기 토큰은 해당 origin의 로컬 저장소에 보관합니다.

공개 웹 미리보기는 같은 Vercel HTTPS 공유 서버를 사용합니다. 서버는 복약 기록과 사진을 비공개 PostgreSQL에 저장합니다. 환자 앱이 열려 있을 때 전송하고, 보호자 앱이 열려 있을 때 10초마다 확인합니다. [테스트 서버 배포·연결 안내](server/VERCEL.md)

개발 PC에서 두 기기처럼 테스트하려면 `보호자 미리보기.cmd` 또는 `node scripts/caregiver-preview.cjs`를 사용합니다. 같은 통합 앱을 8081과 8082에 띄워 각각 다른 역할을 선택할 수 있으며, 로컬 공유 서버는 8789 포트를 사용합니다.

실행과 검증 명령·제한은 [보호자 앱 설명](caregiver/README.md)에 정리했습니다.

## 구현 범위

환자 앱의 하단 메뉴는 복약·진료 일정·내 관리입니다. 복약 탭에는 월간 달력과 선택한 날짜의 복약 현황을 표시합니다. 오늘은 사진 촬영과 기록 수정이 가능하고 지난 날짜는 기록과 사진을 확인합니다. 공유·알림은 내 관리에서 설정합니다. 기존 `/medicines` 주소와 복약 알림은 복약 탭(`/`)으로 연결되며, 새 복약 알림을 열면 오늘 현황으로 돌아옵니다.

| 기능 | 현재 동작 |
| --- | --- |
| 진료 일정 | 병원에서 정한 진료 날짜·시간과 병원명을 직접 추가합니다. 다가오는 일정은 시간순으로 표시됩니다. 일정 삭제는 앱에 저장한 일정과 관련 알림에 적용되며, 실제 병원 예약 변경·취소는 병원에서 진행합니다. 기존 체험 예약은 실제 일정으로 전환하지 않습니다. |
| 내 병원 연락처 | ‘내 관리’에서 병원 이름과 전화번호를 직접 입력하고 수정합니다. ‘내 관리’와 ‘진료 일정’에서 저장한 번호를 확인하고 전화 앱을 열 수 있습니다. 이전 버전에서 같은 병원의 예약 주소를 저장했다면 ‘진료 일정’에서 해당 페이지도 열 수 있습니다. |
| 진료·복약 알림 | 정시·분·시간·일 단위로 각각 최대 8개 시점을 선택합니다. 진료 일정은 최대 30일 전, 복약은 최대 24시간 전까지 직접 입력할 수 있습니다. 기기 권한과 알림을 켜면 선택한 시점으로 등록하며, 지난 알림 시각은 제외합니다. 일정 삭제·복약 완료·시점 변경 시 기존 알림을 정리합니다. |
| 복약 사진 인증·기록 조회 | 오늘 일정에서 촬영하면 사진 품질과 작은 1회분 약봉투의 복용 시간·복용 문구를 자동 확인합니다. 검사 통과 후 사진과 기록 저장이 모두 성공하면 ‘사진 인증 완료’로 표시하고 촬영 화면을 닫습니다. 별도 ‘사진으로 기록’ 버튼은 없습니다. 검은 사진·흐림·문구 부족·판별 불가·저장 실패는 미완료로 남기고 재촬영을 안내합니다. 날짜별 기록·사진 조회와 오늘 기록 정정을 지원하며, 기존 기록을 새 검사에 통과한 것으로 바꾸지는 않습니다. |
| 복약 설정 | 내 관리에서 하루 한 번·아침/저녁·아침/점심/저녁을 선택하고 각 시간을 분 단위로 수정합니다. 오늘 기록이 없으면 오늘 일정과 알림 계획에 바로 반영하며, 기록이 있으면 오늘 일정 전체를 보존하고 다음 날부터 적용합니다. 지난 복약 기록과 알림 켜기·끄기 선택은 유지합니다. |
| 보호자·병원 공유 설정 | 보호자는 같은 앱의 보호자 화면에서 환자 동의와 일회용 코드로 연결해 공유된 복약 기록·사진을 조회합니다. 병원 공유는 공유 의향만 저장하며 실제 병원 계정 연결은 지원하지 않습니다. |

복약 알림은 앱에서 생성된 **오늘 일정** 중 미래의 미기록 일정에 등록됩니다. 다음 날 일정은 앱을 다시 열어야 생성됩니다. 진료 일정 알림은 등록 후 앱을 닫아도 운영체제가 처리하지만 실제 표시 시각은 권한·배터리·집중 모드 등 기기 설정에 영향을 받습니다. 잠금화면에는 약 이름이나 환자 정보 없이 일반 안내만 표시합니다. [Expo 알림 문서](https://docs.expo.dev/versions/v58.0.0/sdk/notifications/)를 기준으로 구현했습니다.

자동 검사는 기기 내부에서 밝기·선명도와 한국어 OCR의 복용 시간·복용 문구 조합을 확인하는 초기 규칙 기반 방식입니다. 아침·점심·저녁으로 나뉜 작은 투명 약봉투를 대상으로 하며, 약국명이 없어도 “아침 식후30분”처럼 충분한 문구가 있으면 확인합니다. “아침 식후”만 읽히면 근거 부족으로 재촬영을 안내합니다. 약봉투의 형태·진위나 실제 복용을 증명하는 모델이 아니며, 글자가 없거나 근거가 부족한 사진은 통과시키지 않습니다. 실제 약봉투 사진으로 인식률·오인식을 검증해야 합니다. 사진은 기기에 보관하고, 보호자 연결에 별도로 동의하면 최근 사진 최대 30장을 연결한 보호자에게 전송합니다. OCR 원문은 기록에 저장하거나 서버로 보내지 않으며 판별 방식·시각만 사진 기록에 남깁니다.

새 자동 검사에는 네이티브 모듈이 필요합니다. **Expo Go·웹에서는 검사기를 사용할 수 없어 새 사진을 완료 처리하지 않으며, 모듈이 포함된 새 설치 앱이 필요합니다.** 기존 사진과 사진 없는 과거 기록은 그대로 조회할 수 있고 소급 인증하지 않습니다. 기록 취소가 저장된 뒤 연결된 사진을 정리하며 앨범 선택·사진 업로드 경로는 제공하지 않습니다.

## 실행

환자 앱과 보호자 앱의 개발 환경과 EAS 빌드는 Node.js 24.22.2 LTS를 기준으로 합니다. 복약 공유 서버도 Node.js로 실행하며 PHP나 Composer를 사용하지 않습니다. 아래 명령은 저장소 루트에서 실행합니다. PowerShell 실행 정책으로 `npm`이 차단되면 `npm.cmd`를 사용하세요.

윈도우 미리보기 실행 파일은 `.nvmrc` 버전을 선택합니다. 같은 환경에서 아래 명령을 직접 실행하려면 저장소 루트에서 `cmd /k scripts\node-env.cmd`를 열고 `node -v`를 확인하세요.

```powershell
npm ci
```

Expo 개발 서버를 켭니다. 기본 포트는 `8081`이며, 사용 중이면 터미널에 표시된 실제 주소를 확인하세요.

```powershell
npm start
```

PC와 휴대폰을 같은 Wi-Fi에 연결하고, SDK 58과 호환되는 Expo Go에서 터미널의 QR 코드를 엽니다. iPhone의 Expo Go는 PC의 Expo CLI와 같은 Expo 계정으로 로그인해야 합니다. 필요한 경우 PC에서 `npx expo login`을 실행하세요. 연결 방법은 [Expo 개발 시작 안내](https://docs.expo.dev/get-started/start-developing/)를 참고하세요.

브라우저에서 화면을 확인하려면 `npm run web`을 사용합니다. 웹에서는 알림 시점과 켜기·끄기 설정을 저장할 수 있지만 기기 알림은 보내지 않습니다. Android 에뮬레이터에서는 기본 알림 수신과 이동을 검사할 수 있으며, 제조사별 절전·잠금화면 동작은 실제 휴대폰에서 확인해야 합니다.

## Windows에서 Android 테스트

이 PC에는 `E:\Dev\Tools\Android`의 Android 도구와 `MetaCare_API36` 테스트 기기를 구성했습니다. Android API 36 / Google APIs / x86_64 / Pixel 7 에뮬레이터이며, 기기 데이터는 `E:\Dev\Tools\Android\avd`에 저장됩니다. 이 `mobile` 폴더에서 목적에 맞는 파일을 더블클릭합니다.

| 실행 파일 | 실행 대상 | 사용할 때 |
| --- | --- | --- |
| `Android 테스트.cmd` | `.preview/builds/metacare-1.0.2.apk` | 최신 1.0.2 APK 실행. 사진 자동 검사와 예약·상담 키보드·스크롤·모션 수정을 포함합니다. 기존 기록을 유지하는 `install -r`로 설치합니다. |
| `Android 미리보기.cmd` | 현재 소스 + Expo Go 58 | 예약 등 UI 수정 직후 확인. 기존 Metro 8081을 재사용하고, 없으면 숨김 창으로 개발 서버를 시작합니다. 새 사진 자동 검사는 사용할 수 없습니다. |

두 실행 파일은 `MetaCare_API36`임을 확인한 에뮬레이터를 재사용하며, 꺼져 있으면 창을 엽니다. 실제 USB 휴대폰에는 설치하지 않고 기기 데이터를 초기화하지 않습니다. APK 앱, Expo Go 미리보기, 웹은 각각 별도 저장소를 사용합니다. 명령 창을 닫아도 에뮬레이터와 개발 서버는 계속 실행됩니다.

기존 버전 테스트 당시 두 `.cmd` 파일을 실제 실행해 APK 설치·실행과 소스 미리보기가 각각 정상적으로 열리는 것을 확인했습니다. Expo Go가 이미 열린 상태뿐 아니라 완전히 종료한 뒤에도 미리보기 실행이 성공했으며, 모두 종료 코드 `0`을 확인했습니다.

미리보기는 PC의 8081·8789 포트를 에뮬레이터에 연결합니다. 8081에서 다른 앱이나 서비스가 실행 중이면 기존 프로세스를 종료하지 않고 안내 후 중단합니다. 개발 서버 시작 로그는 `.preview/windows-test/metro-launcher.log`에 남습니다. Expo Go는 네이티브 권한·플러그인 설정의 배포 검증을 대신하지 않으므로 설치 앱 관련 최종 검사는 APK 모드를 사용합니다.

**APK 1.0.2(빌드 3)는 상담 탭을 제거하기 전의 설치 파일입니다.** 현재 환자 앱은 소스 미리보기에서 확인할 수 있습니다. 아래 미리보기에서 확인한 예약·상담 키보드, 스크롤, 모션 수정과 기존 사진 자동 검사 모듈을 포함해 EAS 빌드·다운로드·서명 검증을 완료했습니다. `Android 테스트.cmd`를 실행해 `MetaCare_API36` 에뮬레이터에 `install -r`로 업데이트하고 앱을 열었으며, 설치 성공과 실행 파일 종료 코드 `0`을 확인했습니다.

설치된 앱의 버전 `1.0.2`·빌드 번호 `3`과 실행 상태를 확인했고 오류 로그는 없었습니다. 기존 하루 한 번 `08:00` 복약 설정과 `0/1` 상태, 10월 30일 `10:30` 예약이 유지됐습니다. 병원예약은 상단 예약 내역 다음에 의사 선택 없이 7열 달력을 표시했습니다. `.preview/windows-test/booking-apk-1.0.2.png`에 확인 화면을 남겼습니다. 이번 1.0.2 설치 확인에서는 새 사진 인증이나 상담 전송의 전체 흐름을 다시 검사하지 않았습니다.

예약 내역을 상단으로 옮기고 확정 예약이 없으면 숨겼으며, 날짜를 선택해도 목록은 유지됩니다. 예약 시간 셀을 제거하지 않고 비활성화해 위치를 유지하며, 예약 페이지에서는 `scrollsChildToFocus={false}`로 기본 포커스 이동에 따른 자동 스크롤을 끕니다.

### 예약 생성·취소와 모션 확인 (2026-10-29)

예약 생성 시 상단 예약내역에 행이 추가되면서 시간 선택 영역이 약 77px 아래로 밀리는 현상을 Android Expo Go에서 재현했습니다. 예약 저장 전에 보고 있던 폼 위치를 기억하고, 상단 목록의 높이 변화만 한 번 보정하도록 수정했습니다. 새 드래그나 저장 실패 시 대기 중인 보정을 버리며, 방문 목적을 펼쳐 놓았다면 저장 후에도 입력란 높이를 유지합니다. 레이아웃 크기를 애니메이션하지 않습니다.

수정 후 같은 Android 생성 동작에서 시간 선택 제목의 화면 Y가 약 412px로 유지됐습니다. 추가한 테스트 예약을 취소해도 기존 예약과 스크롤 맨 위 위치가 유지됐으며, 생성 후 위로 스크롤한 화면이 다시 내려가지 않았습니다. 별도 웹 저장소에서도 첫 예약 생성 전후 시간 선택 제목 Y가 `189.67px`로 같았고, 마지막 예약 취소 시 예약내역 블록이 사라지며 스크롤 `0`이 유지됐습니다. 기존 Android 예약과 복약 기록은 보존했습니다.

버튼 누름·해제(80/130ms), 탭 선택(160ms), 설정창·사진창·토스트·상담 메시지 등에는 짧은 반응을 추가했습니다. 시스템의 동작 줄이기 설정을 따르며 카메라 영상 크기와 스크롤 콘텐츠 높이는 애니메이션하지 않습니다. Android 하단 탭을 눌렀을 때 나타나던 검은 물결 효과도 제거했습니다. RN Web에서 지원하지 않는 `useAnimatedValue` 대신 공통 Animated.Value 수명 관리를 사용하며 실제 웹 로드도 확인했습니다. TypeScript·ESLint와 테스트 73개를 통과했으며 이 변경은 최신 APK 1.0.2에 포함됩니다.

### 상담 입력 화면 수정 (2026-10-29)

Android Expo Go에서 상담 입력창의 떠 있는 필기 키보드를 열었을 때 메시지 영역 높이가 약 22초에 1,297회 변하는 현상을 재현했습니다. 상담 화면도 Android의 중복 `KeyboardAvoidingView` 높이 조정을 제거했고, 메시지 목록 하단을 보고 있을 때만 크기 변경에 따라 애니메이션 없이 하단을 유지합니다. 전송 확인 전후에는 동일한 `clientId`를 컴포넌트 키로 사용해 말풍선이 다시 생성되지 않도록 했습니다. 수정 후 같은 키보드 조건에서 크기 반복 변화가 멈췄고, 화면 키보드로 입력한 `Test` 메시지가 로컬 서버에 저장되고 입력란이 비워지는 것을 확인했습니다. 스크롤로 키보드를 닫은 뒤 말풍선과 저장 시각도 확인했습니다.

예약 화면의 의사 선택은 제거했습니다. 예약내역 다음에 캘린더와 시간 선택이 나오며, 새 예약은 기존 기본 의사 ID로 저장해 데이터 형식과 시간 조회를 유지합니다. 기존 예약의 의료진 정보는 보존합니다. 해당 수정 당시 TypeScript·ESLint 및 상담·예약 관련 테스트 22개를 통과했으며, 상담 입력 수정과 함께 최신 APK 1.0.2에 포함됩니다.

npx eas-cli@latest build --platform android --profile preview

프로젝트 권한이 있는 Expo 계정으로 로그인한 후 내부 빌드 목록에서 APK를 열어 설치합니다. 이 `preview` 앱은 Expo Go나 PC의 Expo 개발 서버 없이 실행됩니다. 브라우저와 설치 앱은 별도 저장소를 사용하므로 웹에 저장된 복약 기록과 사진이 자동으로 옮겨지지는 않습니다. 실제 배포 전에는 `app.json`의 예시 패키지·번들 ID를 정합니다. 자세한 절차는 [Expo APK 빌드 안내](https://docs.expo.dev/build-reference/apk/)에 있습니다.

iPhone 설치용 빌드는 Apple Developer 계정, 인증서·프로비저닝 등 서명이 필요합니다. 내부 배포는 테스트 기기 등록도 준비해야 합니다. 이 프로젝트의 Windows PC에서도 EAS 클라우드 빌드를 사용할 수 있으며, 계정·서명 설정 후 `npx eas-cli@latest build --platform ios --profile preview`로 진행합니다. [EAS 첫 빌드 안내](https://docs.expo.dev/build/setup/)를 참고하세요.

## 운영 서비스로 연결할 작업

외부에서 정한 진료 일정과 복약 기록 중 환자가 동의한 항목만 보호자와 공유합니다. Vercel 테스트 서버는 기기 토큰과 일회용 연결 코드를 사용합니다. 실제 환자를 대상으로 운영하기 전에는 계정 복구·보관 및 삭제 정책·운영 관리를 준비해야 합니다.
